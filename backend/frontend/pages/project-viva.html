Architecture Defense Core Viva Question

"Why did you choose a monolithic Django architecture over microservices for your project?"

Verified Architectural Defense

"For our team size and system scale, a modular monolith in Django provides clear domain boundaries via Django apps without the high operational overhead of distributed transactions, network latency between services, deployment complexity, or tracing distributed failures. Should specific services hit bottlenecks later, modular Django apps can be extracted into standalone microservices cleanly."

Database Defense Schema Integrity

"How did you ensure database normalization, and did you intentionally denormalize anywhere?"

Verified Schema Defense

"All core transactional entities are normalized up to 3NF to eliminate insert, update, and deletion anomalies. For high-throughput analytics, such as student progress dashboards, we computed aggregations via database indexes rather than storing redundant counts that could drift out of sync. Denormalization was avoided to guarantee single sources of truth."

Security Defense Vulnerability Mitigation

"How does your backend prevent SQL injection and CSRF attacks?"

Security Audit Defense

"SQL injection is prevented by utilizing Django ORM parameterized queries for all database operations, ensuring untrusted user inputs are treated strictly as query literals rather than executable SQL syntax. CSRF protection is enforced on state-changing endpoints using synchronized CSRF tokens and strict Origin/Referer header checks."
